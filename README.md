# Blue Pill Bare-Metal Blink

Minimal bare-metal project for an STM32F103C8T6 Blue Pill board using GCC,
Make, OpenOCD, and a cheap ST-Link V2 clone instead of STM32CubeIDE.

## Hardware

- Board: Blue Pill development board
- MCU: STM32F103C8T6
- CPU: ARM Cortex-M3
- Flash: 64 KiB official C8T6 size
- RAM: 20 KiB
- Programmer/debugger: cheap ST-Link V2 clone
- Debug interface: SWD
- Onboard LED: usually `PC13`, active-low

![image](assets/img-20260904-094011.png)

## Toolchain

This project uses:

- `arm-none-eabi-gcc`
- `arm-none-eabi-objcopy`
- `arm-none-eabi-size`
- `arm-none-eabi-gdb`
- `make`
- `openocd`

The project does not require STM32CubeIDE or official ST flashing tools.

`apps/` contains one directory per application. `src/` contains shared runtime code used by all applications. `build/` is generated by `make` and is ignored.

## Build

```sh
make
```

The default application is `blink`. To build a specific application, pass `APP`:

```sh
make APP=blink
```

Generated outputs:

- `build/bluepill-blink.elf`
- `build/bluepill-blink.bin`
- `build/bluepill-blink.hex`
- `build/bluepill-blink.map`

Clean generated files:

```sh
make clean
```

## Flash

Connect the ST-Link clone to the Blue Pill SWD pins:

- `SWDIO` to `SWDIO`
- `SWCLK` to `SWCLK`
- `GND` to `GND`
- `3.3V` to `3.3V` if the probe powers the board, otherwise power the board separately

Then run:

```sh
make flash
```

This uses:

```sh
openocd -f openocd/bluepill.cfg -c "program build/bluepill-blink.elf verify reset exit"
```

## Debug

Start OpenOCD:

```sh
make openocd
```

In another terminal, start GDB:

```sh
make debug
```

The GDB server listens on port `3333`.

## OpenOCD

Local config:

```text
openocd/bluepill.cfg
```

It loads OpenOCD's installed configs:

```text
interface/stlink.cfg
target/stm32f1x.cfg
```

On this machine they resolve to:

```text
/usr/share/openocd/scripts/interface/stlink.cfg
/usr/share/openocd/scripts/target/stm32f1x.cfg
```

The config also contains:

```tcl
set CPUTAPID 0x2ba01477
```

This was needed because your board/probe reported Cortex-M3 debug ID
`0x2ba01477`, while the default STM32F1 OpenOCD config expected a different
value.

## Firmware

`apps/blink/main.c` is a direct-register LED blink.

It:

- Enables the GPIOC peripheral clock through `RCC_APB2ENR`
- Configures `PC13` as a 2 MHz push-pull output
- Toggles `PC13` in a delay loop

No HAL, CMSIS headers, or vendor peripheral library are currently used.

## Startup Code

`startup/startup_stm32f103c8tx.s` is a minimal Cortex-M3 startup file.

It:

- Provides the interrupt vector table
- Sets the initial stack pointer from `_estack`
- Calls `SystemInit`
- Copies `.data` from flash to RAM
- Clears `.bss`
- Calls `main`
- Sends unimplemented interrupts to `Default_Handler`

Interrupt handlers are weak aliases, so defining a function with the same name
elsewhere overrides the default handler.

## Linker Script

`linker/STM32F103C8TX_FLASH.ld` defines the memory layout:

```text
FLASH: 0x08000000, 64K
RAM:   0x20000000, 20K
```

Important sections:

- `.isr_vector`: interrupt vector table, first in flash
- `.text`: program code
- `.rodata`: constants and strings
- `.data`: initialized variables copied from flash to RAM
- `.bss`: zero-initialized variables cleared by startup code
- `.ramfunc`: optional code/data to run from RAM
- `._user_heap_stack`: reserves minimal heap and stack space

Important symbols exported to startup/runtime code:

- `_estack`
- `_sidata`
- `_sdata`
- `_edata`
- `_sbss`
- `_ebss`
- `_end`
- `_Min_Stack_Size`

## System Initialization

`src/system_stm32f103.c` provides:

```c
void SystemInit(void)
```

The current implementation keeps the chip on its simple default clock setup.

It does not yet configure:

- External crystal
- PLL
- 72 MHz system clock
- Flash wait states for high speed
- Peripheral bus prescalers

This is intentional for the first bare-metal blink.

## Newlib Stubs

`src/newlib_stubs.c` replaces the ST-generated `syscalls.c` and `sysmem.c`
files.

It provides minimal Newlib system-call stubs for bare metal:

- `_sbrk`
- `_write`
- `_read`
- `_close`
- `_fstat`
- `_isatty`
- `_lseek`
- `_open`
- `_unlink`
- `_getpid`
- `_kill`
- `_exit`

These are needed because `arm-none-eabi-gcc` uses Newlib, and Newlib expects
some OS-like functions. On bare metal there is no OS, so the project provides
them.

`printf()` eventually writes through `_write()`.

`malloc()` eventually asks for heap memory through `_sbrk()`.

The file also defines weak optional hooks:

```c
int board_putchar(int ch);
int board_getchar(void);
```

Later, implementing `board_putchar()` with UART will allow `printf()` output.

## Removed STM32CubeIDE Artifacts

The previous project contained STM32F411 files, which were wrong for this board:

- `STM32F411RETX_FLASH.ld`
- `STM32F411RETX_RAM.ld`
- `Startup/startup_stm32f411retx.s`

Those were removed from the active project.

The old `Debug/` directory is generated CubeIDE output and is not needed. It is
ignored by `.gitignore`.
